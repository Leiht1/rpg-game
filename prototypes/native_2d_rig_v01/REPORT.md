# 原生 2D 骨骼验证报告 · v01 · 2026-10-16

**结论：共享动作和换装的技术验证成立，视觉验收尚未达到 v11。建议保留原型，暂不替换正式主角，也不立即批量制作 NPC。** 如果接受当前差距，下一步才值得小范围投入角色专用关节美术、权重与人工动作精修；本轮不开展后续工作。

## 视觉判断

当前角色能保留棕色蓬松头发、绿色外套、黄色围巾和暖色手绘卡通的大体身份。骨骼比例在各相位固定，避免了每帧重绘造成的体型漂移。肩/肘、膝和衣袖采用连续加权网格与合理重叠，明显断开的裁片接缝较少。

**仍然存在实质差距：**

- 新头部的发束、眼睛和侧脸与 v11 不完全一致，躯干偏窄，短裤、袖型与鞋型也有差异。不能把相近颜色和高度当作角色身份完全一致。
- 膝部弯曲存在压扁和纸片感；短裤整体随骨盆运动，裤腿没有恢复逐帧绘制的体积与褶皱。连续权重能缓和接缝，不能自动补出弯曲时的正确形体。
- 行走的接触轨迹受控，但双脚开合、身体与衣物的相位细节仍偏规则；原版八帧的姿势塑造更鲜明。它是可用的起步步态，不能据此宣称自然度超过 v11。
- 挥手能证明复用，但沿用同一张手形；手掌朝向、手指张开和肘部轮廓没有专门重绘。只是简单问候动作。
- 网页为 128×128 原生渲染采样，再放大时比 Godot 直接渲染高分辨率网格更柔和。应同时检查 1:1 视图，不能只比较放大清晰度。
- 只制作右侧视角，左侧整体镜像；正面、背面、转身时的层级切换和透视体积都未验证。

骨骼版行走可见高度为 92～93 像素，呼吸/挥手为 94～95 像素，全部未触及画布边缘。站立较高符合行走屈膝的方向，但这些包围盒数据不能证明比例和美术已通过。

## 生产效率与限制

新增呼吸和挥手完全复用同一套图片，第二件上衣也复用三种动作，无需重做动画。这一部分确实减少了“每件衣服 × 每个动作 × 每一帧”重新生成的需求。保存的骨骼层级可以作为相似体型 NPC 的起点。

前期代价仍然明显：必须先绘制完整隐藏结构、设计关节重叠、制作权重和动作。不同体型、长衣、宽袖、不同手形与大幅透视动作仍需重新处理素材、静止姿态或权重。当前动画使用较密的烘焙关键帧，后续需要人工整理和精修，不能把它当作低操作成本的成品动画模板。没有进行动画师工时对照，因此不报告虚构的效率倍数。

运行时只有原生骨骼动画和网格渲染，不依赖 Python，也没有用程序平移静态整个人物冒充行走。离线起步工具会计算关节姿势并保存为普通动画轨道；运行与编辑均使用保存的 Godot 资源。

## 验证证据与边界

环境：Godot `4.7.2.stable.official.ed1daf0bf`，Windows，OpenGL Compatibility，NVIDIA GeForce RTX 3060。没有修改正式角色模板、移动逻辑、地图、相机、碰撞或正式场景；没有安装依赖，没有运行 Blender。

- `evidence/native_tests.json`：原型专项通过、0 failures。检查骨骼及网格有效性、权重归一化、实际多骨混合、骨骼轨道、浮点旋转关键帧、三动作循环端点、腿长、膝盖方向、动作切换复位、换衣后变换/相位一致、暂停/慢放/步进/镜像/周期调整。
- 网格共 1728 个三角形，其中 305 个顶点有多骨权重。没有测量游戏中的运行帧耗时或 FPS；原型同时显示两个骨骼角色，不能作为正式场景性能结论。
- 每周期 128 个数值采样中，膝相对弯曲约 `25.28°～67.80°`，无反关节。支撑期脚踝对预设直线轨迹的最大误差约 `0.00545 px`，垂直误差约 `0.00534 px`；支撑时脚掌保持水平。
- 上述轨迹是原地行走的虚拟地面模型：每周期对应约 32 像素相对地面行程，约 55.2 px/s。**没有接入正式游戏 200 px/s 移动，不能用此误差声称实机移动零滑步。** 正式移动与步幅的适配需另行论证。
- `evidence/delivery_checks.json`：每个动作/服装各 64 张实际 GPU 渲染。呼吸与挥手在脚部检查区 `[45,96,86,116]` 的整周期 RGBA 最大变化均为 0，说明该区域没有上下漂浮。画布边缘无裁切。
- `source/protected_baseline.json` 对照 111 个正式文件保持一致，`reference/` 的十二张原版帧也与正式输入字节一致。没有重新运行全量游戏回归。
- 独立交付副本在不携带 `.godot` 缓存的情况下完成 Godot 首次导入与主预览启动，无资源或脚本错误；交付包不依赖正式工程路径。
- 网页实际操作核对动作、两套上衣、骨骼、镜像、正常/慢速、暂停、相位和步进；周期通过数值控件调整。截图见 `evidence/browser_preview.png`，原生窗口见 `comparison.png` / `wave_bones.png`。

数值与资源检查仅证明功能和有限运动约束，不代替人工观看连续动作与美术验收。环境工具诊断为 WARN，详细原文见 `QA.md`；不能表述为所有检查无警告。

## 是否继续投入

值得保留并小规模继续研究，原因是换装与新增简单动作的复用已经真实成立。是否扩大投入取决于能否用少量针对性的关节和轮廓修绘消除纸片感，并保留 v11 的人物身份。如果仍需为每个大姿势大量补图，骨骼的生产优势会明显收窄。

本轮推荐：**技术验证通过，正式美术替代暂不通过；保留 v11，等待用户验收。** 未自动追加素材生成、正式接入、前后视角、NPC、换装系统或 3D 实验。

实现参考：[Godot 2D Skeletons](https://docs.godotengine.org/en/stable/tutorials/animation/2d_skeletons.html)、[Polygon2D 原生骨骼权重属性](https://docs.godotengine.org/en/stable/classes/class_polygon2d.html)。

## 云端隔离证据

使用已有迁移快照 ht.json，在独立 `docker run --rm --network none` 中运行旧双角色规则探测；独立 Runtime 目录，未使用正式Data挂载、未停止正式容器。app/bin只读，测量脚本运行在既有测试home目录。本轮未部署、发布、提交、推送或改写正式玩家存档。

原云端规则剔除2轮冷启动后8轮：双角色整轮中位599.62ms，拾取178.60ms。规则日志共享推进163–561ms，恢复约35–144ms。该实验无公网请求和SQLite提交，说明规则执行本身足以造成明显等待，但不能量化公网/磁盘在真实请求中的额外贡献。

临时覆盖环境脚本仅加计时，积雪推进采样116–286ms，占共享推进最大部分。临时挂载**本轮前已有**season_surface.gd热源复用候选后，双角色整轮439.66ms，拾取215.735ms（cloud-existing-candidate.log）。整轮改善，拾取未改善；不能把既有候选记为本轮新修复，也不能宣布采集延迟解决。

环境计时草稿两次挂载失败：一次本地默认GBK读取失败，后续命令未及时停止；一次上传未完成即尝试挂载。Docker为不存在的源创建了测试目录，均未触及正式app文件。最后使用/tmp独立文件和只读覆盖成功。草稿保留用于追踪，不是运行资源。

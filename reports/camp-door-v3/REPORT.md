# 门条纹与竖门转角打不开 · 修复报告

2026-10-18 · Godot4.7.2 Stable / Windows / Compatibility OpenGL3.3 / RTX5060。

## 已修复

### 门侧面黑色重复条纹

上一版把同一张完整木纹/绳结图反复绘制到24块各40单位高的侧面上，各片重叠并重新从头采样纹理，形成截图中的密集条带；开门中途侧面与正面也会互相覆盖。上一轮只检查逻辑和截图，未覆盖分片相对完整纹理的图像差异。

本轮改为一个连续纹理表面：正常角度保持门面连续UV；严格侧向保留完整8单位厚度，将整张侧面按屏幕Y分为互不重叠的24条带，共享位置和连续UV，不重复贴整图，不叠第二层门面。采用多边形共享UV以避免TextureRect源区独立边缘采样引入细缝。仍保留每片的实际脚点Y排序，门框、碰撞和旋转角关联不变。原20张批准PNG（v1的16张+v2的4张）全部哈希一致，无图片生成或资源替换。

### 竖门转角被误认为“站一侧但两侧打不开”

只读查看既有建筑布局后，在隔离测试中复现了相同连接关系：竖门的上端接横栅栏，人物站左侧。原来固定上端轴，向右开会真实撞到上沿横栅栏，向左开又会扫到人物，所以两条旧路径都会拒绝。这不是应当通过删除碰撞解决的情况，而是旧固定轴限制没有覆盖正常转角使用。

竖门在关闭状态准备打开时，先尝试当前轴朝远离人物的方向；受阻时，尝试另一端固定门柱作轴，仍优先远离人物。远离侧两端都不可用才检查朝人物一侧的两条路径，四条都真实受阻才拒绝。门柱始终不移动，门轴只在关闭状态选定，整个开关动画和打开状态期间固定。关闭沿本次轴及swing，允许同站位连续开关。水平门沿现有轴，保留上一轮两侧自动选择。

新增可选hinge_end=0/1并入原建筑实例快照；旧档没有此字段默认为原轴0，原存档版本、ID、格点、占用、成本和路径保持。动画、门板碰撞、Y排序都引用同一门轴；保存失败连同open/swing/hinge_end原子恢复，原本没有字段的旧实例失败后仍无字段。非法字段拒绝读入保护源档。

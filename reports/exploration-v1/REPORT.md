# 连续探索 V1-A 第一轮交付

日期：2026-10-24。运行 Godot 4.7.2 Windows / OpenGL Compatibility，项目默认1280×720。本轮已实现并验收，不止现状检查。未部署、发布、提交或推送，未读写正式玩家存档；本机原有游戏/编辑器进程未关闭。

## 已实现

普通入口增加一段连续流程：发展达到资格 → 独立安置唯一遗迹 → E调查遗骸/背包 → 地图与残页入包 → 按大致方位找到湖岸旧记 → 使用已有鱼竿和钓鱼判定取得神秘瓶子 → 在物品菜单“打开”阅读 → 保留废弃矿洞线索。

资格采用**已有的非废弃金属加工台 + 第4天起**。实际核对了现有设施、铜锭成本和金属工具/钓竿配方；它能代表已进入冶炼发展，不引入虚构科技等级或制作记录。时间检查按原世界日历，不是每个玩家入服后的单独计时。具体实现与权威参数只维护在[探索规范](../../EXPLORATION_SYSTEM.md)及 `scripts/exploration_chapter.gd`。

资格、安置、调查、湖岸阅读、瓶子领取与瓶子阅读分开记录。安置沿 Seed 确定候选次序，保存坐标后不重新抽签。生成复用湖岸候选、陆地可达、景物净空及资源分布，避开出生区、现有建筑/篝火/遗物/商人及保留矿点。不改大陆生成器，不删树清资源；无安全位置则等待。

地图与残页同一事务发放；只剩一格也不部分发奖。瓶子仍是原库存真实物品，领取本身不完成阅读；三个关键物品都可保存、重读并保留，不能销毁/丢弃。全世界唯一奖励归实际领取者，其他人可在遗迹重读地图和文字；瓶子打开后，湖岸旧记保存共享抄录，未持瓶的玩家也能重读矿洞信息。

普通钓鱼掉落表不变。目标湖的特殊钓获有最多三次已提交成功收获的保底；目标岸边还有同一钓鱼系统的调查钓位，解决该湖没有活动鱼群时的阻断，不补充或重置普通鱼群。满包、失败、取消、写盘失败不推进保底。并发结算使用最新世界状态，瓶子只领取一次。

前期没有海域、岛屿、造船、航海或最终宝箱提示。无主线追踪器、新地图标记、完整 NPC、矿洞入口、炸药、谜题或后续战斗内容。

实际窗口测试包含：

- 新世界无遗迹/占位物，未达资格重载仍不触发；用已有建筑管理器正常扣除测试材料建成金属加工台，单有设施仍不触发，再用原日历推进跨过时间保护。
- 资格阶段先提交，再安置；地点可达、距出生区足够远、不压资源；离开与返回位置稳定；按真实E输入通过原选择逻辑打开调查页。
- 满包和只剩一格不丢地图/残页；刻意指向不存在目录制造真实写盘失败，库存和阶段回滚；原原子写盘后从隔离JSON恢复原地点、物品和阶段。
- 湖岸调查解锁钓获，原普通掉落表及实际湖鱼奖励保持；同一原钓鱼抛竿/判定/成功流程完成保底瓶子。用原物品右键菜单按钮“打开”瓶子，确认获得与阅读分离、重读无奖。
- 清空目标湖活动鱼群后仍可在调查钓位使用鱼竿；成功动画先显示实际瓶子；收获写盘失败保留领取资格，之后成功领取。
- 宿主拒绝未知存档版本、远程伪造调查和无物品阅读；缺少新字段的旧格式安全初始化。第二个角色合并共享进度不复制奖励。新宿主进程恢复精确阶段、坐标和库存。
- 两个独立图形客户端通过私有HTTPS服务同时提交调查/钓鱼；检查双方角色、权威快照、确认阅读页。真正清除客户端令牌、登录新会话、resume并重新进入人物后，仍保持阶段5。

测试世界使用Seed271828。材料、初始联机测试阶段/角色位置和保底计数由隔离夹具准备；没有向正式玩家发放测试品。单人用原日历加速推进三游戏日，未花现实三小时等待；本机双端钓鱼通过运行中的原计时条选时发送真实判定请求，未直接注入瓶子奖励。

最终实景逐张检查过遗骸/背包/纸片、调查页、湖岸旧记、瓶子成功动画、矿洞阅读页和两个客户端共享抄录页。纸质面板没有截字，复用原主题和关闭声标记。截图仅作本轮待确认临时媒体，已由.gitignore排除；用户确认后按原规则清理。

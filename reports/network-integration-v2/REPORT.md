# 双人联机集成与羊毛衫袖口修订

2026-10-24。Godot 4.7.2，项目默认1280×720。使用真实独立HTTPS服务器、独立Godot规则进程及两个独立原生客户端进程；主要轮次使用本轮重新生成的Windows客户端、服务器EXE和PCK。没有可操作的第二台电脑，**全部双端结果都是本机测试，异机局域网未验证**。

所有账号、证书、SQLite世界和人物均为隔离测试数据。正式配置、部署、账号和玩家存档没有被本轮测试写入；没有发布、部署、提交或推送。测试包仅在 `reports/.tmp/network-integration-v2/runtime`，不覆盖原分发或服务器。

## 修复

1. **冷启动阻塞登录**：原服务在全局事务锁内启动Godot世界规则进程、生成默认快照，新世界地形生成也持有同一把锁；另一人的登录会被阻塞到8秒连接期限以外。现在启动与生成在锁外完成，同世界启动只进行一次，权威结算及提交仍在原事务中，提交时重新检查会话/世界归属。已启动世界的读取不等待其他世界的启动锁。新世界生成或保存失败清理本次未提交缓存，不消耗世界归属。没有放宽登录超时，也没有靠推迟第二人登录解决。
2. **延迟下移动确认饥饿**：新增预热检查原先先竞争状态锁、之后才登记移动优先队列，快照无法看见已经等待的移动请求。改为在任何锁等待前登记，异常路径也释放计数。附加220ms延迟的原失败中出现1.59–2.94秒确认等待和预测暂停；修复后最终双端采样暂停均为0。
3. **打包TLS启动失败**：本机Python发行版创建SSLContext时读取相邻的TLS策略PEM，冻结构建最初未携带它。构建改用当前解释器，并在存在该策略文件时一并打包；保持原公开证书及严格名称校验。真实打包服务器已完成启动、双端及重启验证。通用500错误新增仅含异常类型/代码位置的诊断，不打印请求数据、凭证或异常载荷。
4. **羊毛衫袖口比手窄**：按用户补充反馈，通过generate2dsprite流程和内置image_gen编辑原袖片，采用较宽、较直的罗纹袖口。三向新袖图位于 `assets/season_gear/sleeve-v2`，原V1 PNG保留。40×100居中画布两侧各增加4像素，原手掌复制到x=4，局部坐标、Grip、比例、动画及肤色区域不变；y≥86的原手部字节保持。袖口有效横幅[2,37]覆盖原手掌[4,35]。原图、提示词和来源见该目录provenance及 `art/wool-sleeve-v2`。

## 失败记录与测试前置修正

- 早期打包轮曾出现通用500、TLS启动失败、移动超时及测试输出路径失败；原主轮次日志保留。TLS缺文件、全局锁阻塞和移动登记顺序已修复；通用500的早期包未留下可归因异常栈，串行完整重打包后的最终衣帽/基础/延迟/重启轮通过，并补上安全错误位置记录，不将该旧尝试虚构为已单独定位。
- 原旧战斗脚本仍断言“未同意切磋不伤害”，与当前已移除切磋的自由PvP规则冲突。修订为验证实际连续命中；每次攻击先真实走回射程、等待服务器动作完成，再刷新受击者快照核对伤害。原“按F后固定等1.3秒”不保证命令已被服务确认。低血野猪夹具改为1生命，避免12生命在命中前自然回血后不致死；未改变真实伤害或死亡断言。
- 旧野猪“踩到即毁作物”断言按当前规范更新为夜间攻击前保留、命中后毁坏且不发奖励；墙/栅栏保护继续检查。旧季节盘的父节点已随时钟显隐，坐标断言改用真实画布坐标并核对父节点。
- 衣帽初稿工具耐久夹具超过实际100上限，已改合法实例；移动展示补上双方已进入该观察阶段的同步，避免一方先释放按键后另一方才开始观察。打包资源的 `res://` 不可作为报告写入目录，改用工作区绝对路径。
- 基础玩法初稿在出生入场阶段尚未结束时按E，正确被原输入保护拒绝；现在先断言服务已进入alive再操作。没有改变客户端入场保护，也没有恢复登录顺序屏障或削弱拾取断言。
- 袖口独立夹具卸下时最初未重放原动画纹理轨道，现按真实角色每帧顺序验证恢复；原手掌与握点检查保持。

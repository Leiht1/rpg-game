# 联机流畅度 V9（已发布 2026.10.23.4）

2026-10-23，Godot 4.7.2。当前优先处理双人联机，未扩展其他玩法。

## 修改

- 地图探索恢复按 1024 字节分块比较，跳过未变化块，仅更新变化位；保持原图对象、校验、清除和旧档格式。
- 地图缓存预热可以在一行中暂停，避免处理整行才检查预算。相同坐标仍调用原绘图算法。
- 相同建筑按 JSON 数值语义比较，避免整数/浮点表示变化触发重建。
- 大型玩法回复在客户端支持时使用 gzip，压缩在事务锁外进行；不支持压缩的旧客户端仍收到原 JSON，原状态和存档不压缩、不改格式。
- 本机攻击入队立即预演姿势及原攻击移动限制；不提前扣体力、判命中、改伤害或写档。确认后连续接续动作，结束、拒绝、受击或死亡取消预演。等待确认不重复排攻击。
- 延续 V8 的移动精简回复、轮询与命令分离、过期列表拒绝。V8 其他配方、地图标记和外观修改保留，详见其报告。

## 实测

同机两个真实图形客户端、完整 1536 地图、默认 1280×720、隔离 HTTPS 服务。每轮往返移动 20 秒、各攻击 3 次，随后采样 1 秒；每端约 1270 帧。第二轮在移动、快照、命令和轮询请求进入服务前额外等待 100ms，模拟通信延迟；不模拟丢包、限带宽或真实异机。

| --- | --- | --- |
| 实际帧间隔中位数 | 16.65 / 16.66ms | 16.65 / 16.64ms |

| 远端角色节点缺失/不可见帧 | 0 / 0 | 0 / 0 |
| 远端攻击状态可见帧 | 60 / 115 | 58 / 118 |

逐帧采样使用实际单调时间，不用可能被引擎裁剪的 delta。旧性能测试开启逐条 stdout 诊断时产生明显额外开销，不能把那些长帧全部归因于正式游戏；此前 V8 的帧耗结论应按此修正。现改成内存汇总、采样结束后输出，实际帧时间仍包含正常网络解析与状态应用。

这不是伤害确认延迟：普通轮次命令往返中位数约248/136ms（各仅3次），额外延迟轮次约270/214ms，服务器权威结算仍需等待。首次规则宿主冷启动仍约16秒，不包含在21秒画面采样内。不能把本机动作响应写成服务器命中耗时。

原始指标：[普通双端](local-two-player.json)、[额外延迟](delayed-two-player.json)。本轮没有异机人工实测、长时间远途探索、多人负载或像素级人物遮挡验收，节点可见性不等于所有场景的视觉问题已消失。

## 定向检查

- 探索恢复：6次约2.8–3.6ms；新增/清除、原图对象、校验拒绝、1024字节边界和最后非整字节检查通过。
- 地图预热：同一块跨20次调用完成，最大构图切片0.636ms，角点/中间像素与原算法一致。
- 攻击预演：即时姿势、不扣权威体力、阻止重复、确认时不倒放、结束/拒绝/受击取消检查通过。
- 压缩：gzip协商、q=0/q=0.0禁用、无支持回退及解压后JSON完整一致通过；构造的大量相同地图位图回复压缩后小于原2%，不是实际世界带宽统计。真实Godot双端验证可解压使用。
- 14项真实规则宿主/服务战斗事务检查通过，包含伤害、回执去重、死亡和失败回滚。首次运行因测试默认引擎路径不存在未执行，指定本机实际引擎后通过。

源码专项使用隔离数据；发布阶段按用户授权备份并更新正式服务器，未提交或推送。

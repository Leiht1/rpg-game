# 联机同步、拾取与新角色修复 · 2026-10-22

## 原因与修改

- 双人请求在服务全局锁内重复推进所有角色，再单独重建请求者快照；移动与轮询一起排队。合并请求者推进和操作，同世界短间隔快照复用已提交状态，执行器已就绪时不强制多等一帧。保留原服务权威、输入确认与重试幂等规则。
- 移动回复附带同世界人物位置；远端使用服务器采样时序丢弃过期包，短时补间并限制每帧追赶距离，避免慢回复后的跨步跳变。
- 已拾取节点未从区块掉落列表移除，交互查找读取已释放对象，隔离复现甚至触发引擎崩溃。现在同步移除、隐藏、标记，并在读取节点前检查生命周期。旧掉落缺少 id 的情况在服务迁移和库存载入处按原字典键补齐。
- 新单机和联机角色均不再赠送服装；既有人物库存、装备不删不改。旧初始化标记保留以兼容原存档格式。
- 无效世界名先校验再计入创建限额；客户端空名直接提示输入，失败不消耗服务限额。

## 定向验证

Godot 4.7.2，项目默认1280×720，隔离账号与临时世界，1536格，未操作真实玩家账号或测试物品投放。

- 修改前本机双客户端：移动请求含排队中位515ms、P95约1030ms；两个客户端分别出现19/50个预测缓冲满后停止的帧，虽然画面帧率仍约60FPS。
- 源码最终双客户端48/41项通过：双方实际E拾取、对方掉落消失、已销毁对象清除、一人退出后另一人继续E拾取、库存结算、走停和重新进入。预测停止帧均0，移动无回退，停下漂移0。远端位置样本12/13个（约3秒），单帧最大15/10像素；帧时间P95约16.7ms，一端仍有3个超过33ms的帧。
- 服务端4个定向用例通过：无效世界名不耗创建额度、新角色空库存及已有库存保留、共享推进合并与重复请求不重复执行、保存失败回滚。
- 单机原生窗口新角色空库存/初始化标记/隔离存档通过。交互生命周期回归通过。远端过期包/逐帧位移上限/停止收敛回归通过；该不入树的角色单测仍有退出时1个CanvasItem与1个ObjectDB诊断，不冒称无退出诊断。

## 验证边界

本机双客户端短程测试不能代替两台电脑的长期实玩。共享规则仍由原服务串行处理，首次大世界冷启动仍较慢，并发进入与冷启动交叠时曾出现超时；本轮双客户端先完成登录与角色进入再测试持续玩法，没有把这一边界算作已修复。远端采样仍存在数百毫秒间隔，不能宣称所有网络延迟消失；本轮修复的是重复结算排队、远端突跳及拾取失效的具体原因。未做16人负载、全量回归或多分辨率测试。

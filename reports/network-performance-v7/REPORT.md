# 联机整合与性能 V7 · 2026-10-23

本轮将此前本地改动接入同一客户端及权威规则包：传送门、工具与攻击动作/图层、野猪行为、光源叠加、攻击移动限制、提灯实例快照、营地火把燃料、野外武器栏与木棍配方、生存指南与资源修订。指南新角色从第一步开始，按角色保存；旧角色缺字段视为完成，不向原档投放测试物品。

## 优化范围

- TLS握手移到各连接线程，扩大连接队列，避免慢握手卡住后续玩家。
- 常驻规则进程改用带随机凭证、长度上限和超时保护的本机TCP通道，替代逐请求文件邮箱；保留事务回滚与进程回收。
- 普通只读接口不再复制/保存全世界；移动暂存当前人物及探索行，位置检查点每0.5秒提交，其他成功事务仍立即提交。强行终止可能损失最近不足0.5秒的位置变化，不延迟背包/制作/交易/伤害事务的成功确认。
- 移动优先于已有普通快照请求；世界推进按实际间隔合并，避免同一轮被每个玩家重复推进。
- 无画面规则进程不生成地表纹理，不持续刷新界面；普通快照不等待周围地图画面加载，交互/战斗必要场景仍按原规则检查。
- 客户端合并尚未发送的连续同向移动输入，单条时长仍不超过50ms；已发送输入不可修改，转向/跑步变化另记，原服务端时间额度及碰撞校验保持。每批最多1秒，延迟后的积压分批补交；空闲推进间隔0.75秒，战斗仍0.2秒。已加载地图区出现新掉落物时，交互入口从权威存档补建对应对象，避免目标不存在而拒绝拾取。

## 失败记录与边界

优化过程中多轮四端测试触及原85条预测队列上限；仅关闭界面刷新或取消普通快照地图等待，并不足以稳定消除停顿。追加输入合并后，还暴露过长积压超过服务器1.75秒时间额度后反复拒绝的问题；最终每批限制1秒，并降低空闲重复推进开销。该失败聚合另存 packed-4-merge-before-batch-limit.json。保留合并前聚合数据 packed-4-before-input-merge.json、packed-1-before-input-merge.json。

早期单人长距离路线曾出现最大确认间隔2404ms、43帧暂停；该路线走出只验证500单位的走廊，实际达到1157单位，不与安全路线结果混同。最终持续往返测试限制在已验证走廊内，连续20秒、10次两秒方向交替。远距离探索、战斗密集区、跨机器及关闭代理后的实测仍不能由安全走廊结果代替。

双端功能测试初次夹具使用了返回值副本，补正后又发现大地图正式出生门与旧导航出生坐标不同；将测试物品置于实际出生门附近后重跑。自动更新首轮测试缺少旧版current.json，补上完整旧安装后通过。报告生成曾因默认GBK解码失败，改用UTF-8；均未改变正式程序。

首次1536格世界规则进程冷启动约24–28秒；四个真实窗口在同一台电脑争用CPU/GPU，不能据此承诺四台设备的帧率或公网延迟。未测16人、长期负载或关代理后的异机连接。

联机战斗测试最初因旧机器Godot绝对路径及测试人为时钟恰落0.2秒浮点边界失败，改为可配置路径及0.21秒夹具后最终14项通过；未将失败次数计为通过。

## 代理核查

本机系统代理指向127.0.0.1:7897；未发现代理环境变量或TUN IPv4路由。Godot请求及自动更新使用直连HTTPS，没有配置应用代理。服务器为独立后台进程，启动不依赖Codex连接。历史客户端SSL EOF只说明连接断开，不能据此认定服务器进程退出原因。代理的全局/TUN模式仍可能改变网络路由，需要用户关闭代理后的异机对照。

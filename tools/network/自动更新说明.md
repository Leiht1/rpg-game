## 更新与保留规则

- HTTPS 校验证书和主机名；固定公钥验证 Ed25519 清单签名，校验压缩包和每个运行文件 SHA256。
- 完整下载到临时文件，受控解压到新 Versions 目录，完成校验后原子切换 current.json。失败保留原版本；成功切换后仅保留当前版本和最近的一个旧版本，删除更早的已签名版本。文件占用导致清理失败时，下次成功检查更新重试，不阻止游戏启动。
- 根目录 Config 保持；个人存档及账号记忆继续使用原游戏用户目录，发布包不含服务器 Data、账号或私钥。
- 同一启动器目录只能开一份启动器；启动器在游戏退出前持续持锁。根目录需可写。
- 当前为完整包更新，不支持增量、断点续传和启动器自身更新。启动器代码有变更时需替换启动器或重新分发首包。本次两版本保留功能需已有用户关闭游戏和启动器后，使用 `dist/Windrest-Launcher-Retention.zip` 中的 EXE 覆盖原根目录启动器一次，Config、Versions、current.json 保持。回退游戏内容需以新的版本号和更大序号发布旧内容。
- 旧版本能否联机取决于服务器兼容性；“启动已安装版本”只保证可尝试启动。

实现及验证见 [报告](../../reports/auto-update-20261022/REPORT.md)。

## 开发电脑分发包清理

完整首包目录与ZIP成功生成并通过压缩完整性检查后，发布工具自动清理同目录 `Windrest-AutoUpdate-版本` 的旧完整包及同名ZIP，只保留当前版和上一版；失败构建不清理，占用失败留待后续成功打包重试。仅匹配该命名，不触及运行部署、Data、deployment-backups、其他临时构建目录或未知文件；跳过链接与junction。

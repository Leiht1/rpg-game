# 风栖原野 V0.1 · 公司局域网测试

当前为完整玩法联机 V5：原背包、制作、采集、建造、储物、料理、工业设施、种植、动物、钓鱼、商人、身体/睡眠、昼夜天气、照明和地图均已接入服务器结算。验证范围及限制见项目根目录 MULTIPLAYER_V01.md 和 reports/network-gameplay-v5/REPORT.md。

## 服务器电脑

使用 `dist/network-v0.1.0`。Server 是程序，Config 是配置，Data 是实际账号和世界。更新程序只替换 Server；保留整个 Data 及配置，不用新空目录覆盖。

1. 首次运行 `Initialize-Server.cmd`。只初始化一次，重复运行会拒绝，不会重置账号。
2. 在本机打开 `Data/Accounts/FIRST-ACTIVATION.private.json`。其中有 TEST-001 至 TEST-008 和独立 ADMIN-001 的一次性随机凭证。逐人私下发放其一条，不把整个文件发到群里。管理员单独保管 ADMIN-001。
3. 运行 `Start-Server.cmd` 并保持窗口开启。Ctrl+C 正常停止服务器；关闭客户端不会删除角色。
4. 默认监听 TCP 24870、最多16会话。公司测试使用当前电脑内网地址；地址变化时重新准备客户端配置即可，无需改联机代码。

协议采用 HTTPS/TLS，使用 TCP，不使用 UDP。相同局域网不需要路由器公网端口转发。请按公司网络规定允许此程序的 TCP 24870 入站；没有自动修改公司防火墙。Wi-Fi隔离、不同VLAN或公司策略可能仍阻止连接，必须由另一台电脑实测。

本机添加规则的尝试被Windows以权限不足拒绝。可由有权限人员运行项目的 `tools/Allow-LAN-Server.ps1`，仅允许此程序、本地子网、TCP24870。当前交付现场服务器已在后台启动；项目的 `tools/Stop-LAN-Server.ps1` 可停止这一部署目录的进程，之后可用 Start-Server.cmd 前台重新启动。

## 发给同事

在初始化后，从 PowerShell 运行项目的 `tools/Prepare-LAN-Client.ps1 -Address 服务器内网IPv4`。它只复制公开证书、更新客户端配置并重新生成 ZIP，不复制账号、密码、激活凭证、私钥或世界。

把 `dist/Windrest-Client-v0.1.0.zip` 发给同事。完整解压后双击 Windrest.exe；不要只取EXE。必须保留 Windrest.pck、Candidates.pck、LoginVault.exe、Config 文件夹。同事无需安装 Godot 或 Python。

登录成功后始终记住用户名；默认不勾选「记住密码」，勾选才加密保存并在下次预填密码。取消勾选立即清除保存的密码。密码绑定当前Windows账户，只存于本机用户目录，不写入分发包；仍需点击登录。更改密码成功后同步更新已记住的密码。

完整玩法修订1、移动确认修订2需要同时更新客户端和独立服务器。服务器更新时先停服和备份，替换整个Server目录，保留原Data及原Config其他配置，并在Config/network-server.json设置 gameplay_preview 为 true（沿用开发期字段名，表示启用完整玩法）。不重新初始化；所有测试者重新解压最新客户端并重新登录。BUILD.txt 应显示 full gameplay V5；旧客户端进入世界会被明确要求更新。

首次点「首次账号激活」，输入分配的内部ID/凭证，自己绑定唯一英文用户名和10至128字符密码，再设置昵称。以后只使用用户名和密码登录。管理员从个人资料进入服务器管理；世界创建者没有管理权限。

登录后选择联机模式，创建或加入同一个世界。新角色选择性别、发型和肤色；每个新角色只发一套候选测试服装，可在B背包中装备。沿用原游戏操作：WASD移动、Shift奔跑、1～8快捷栏、B背包、M地图、E交互；Y打字、Enter发送、Esc取消。制作、建造和设施使用原游戏界面。正式世界不注入测试箱或测试材料。

同一世界共享资源、掉落、建筑、箱子、设施产出、动物鱼群、天气时间和探索进度；每人分别保存随身物品、身体、制作与钓鱼状态。床铺占用会阻止另一人重复入睡，E醒来。旧联机箱子、掉落和遗产会在首次进入完整玩法时转为原生地面物品，保留数量及实例。无人在线时暂停世界模拟，不承诺离线生产。

返回大厅、关闭游戏、断线均保留角色。换世界必须使用「永久退出当前世界」并确认；随身实物会留下遗产。管理员删除世界要求无人在线并先自动备份。

## 证书、备份与迁移

客户端只持有 `server-public.crt`，严格验证TLS和服务器名称，不跳过证书校验。`Data/Accounts/server-key.private.pem` 和激活文件只能留在服务器；Data 在初始化时移除继承访问权限，只授权当前Windows用户和SYSTEM。迁移后以新的运行账号重新启动以设置权限。

服务器每次启动及删除世界前备份数据库、Accounts（含私钥/头像）和Worlds到 `Data/Backups/*.zip`。这些备份含敏感凭证，不能当客户端资源发放。管理日志只存操作名与服务器ID，不存密码或聊天正文。聊天仅在内存中保留数秒。

迁移：停止服务器 → 备份整个Data和Config → 把Server、Config、Data复制到新Windows电脑 → 检查Config中的相对路径 → 启动服务器 → 更新客户端内网地址。保留原证书/私钥，无需重新激活账号。不要重新初始化既有Data。

恢复：停止服务器，把当前Data先改名保留，再将完整备份内容恢复到Data。若只恢复某个ZIP，需包含state.sqlite3、Accounts、Worlds和公开证书；不混用另一份数据库的sqlite3-wal/shm文件。未知格式或不兼容生成器拒绝覆盖，未实现跨版本迁移器。

## 开发构建

源码配置位于 config/。源码模板默认localhost和独立server-data；分发配置位于客户端Config，部署服务器配置位于部署根Config。机器地址仅在配置中。

安装 tools/network/requirements.txt 后，用 `python tools/network/build.py --godot <Godot控制台程序完整路径>` 构建。客户端/地形和库存执行器使用官方Godot引擎运行器与PCK，服务入口为打包Python程序；没有使用专用发布导出模板，尚非体积优化发行版。源码中的候选目录保持.gdignore，仅将运行所需四个候选目录独立打包。候选美术依然待审核，未迁入正式assets。

客户端与服务端版本0.1.0、协议1，存档格式1。版本不兼容会明确拒绝。修改端口时同步更新服务器port和客户端server_url；修改服务器程序前先备份，勿删除Data。
